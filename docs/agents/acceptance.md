# 验收清单（专题）

> 本文是 [AGENTS.md](../../AGENTS.md) 的专题延伸。发版前、或大改动之后过一遍；条目与各专题文档的规则一一对应。

- [ ] `pnpm tauri dev` 启动无报错
- [ ] 进程列表正确显示有音频会话的进程
- [ ] 显示名：有窗口的程序在左栏首行、hub 卡（及其按钮的 `aria-label`）显示**可见**窗口标题（浏览器换标签跟着换名且不写「进程列表变化」日志）；托盘常驻或 UI 在别的进程里的程序显示版本资源描述（steam.exe → "Steam"，不是隐藏窗口的「无标题」；msedge.exe → "Microsoft Edge"，不是被砍半的 "Microso"），两者都没有时回退 exe 名；左栏第二行在两者不同时保留 exe；搜索两个名字都命中
- [ ] 图标：左栏每行与中心显示 exe 图标（同 exe 的多个进程只有一份，也只发一次询问）；像素异步到达时行不移位（占位槽尺寸固定）；问的瞬间 pid 死掉或提取一时失败，后续刷新自动补问、图标自己回来；真正无图标的程序稳定显示首字母，不报错
- [ ] 设备列表正确显示渲染设备
- [ ] 路由操作成功（进程音频切换到目标设备）
- [ ] 停止路由后程序跟随系统默认设备：之后手动切换默认输出，它也一起走（2.1.1 的回归点）
- [ ] 路由期间退出应用：程序不再被固定在旧设备上——**三条出路都要试**：托盘「退出」、关掉最后一个窗口（走 `RunEvent::ExitRequested`），以及**注销 / 关机**（那条路径根本不经过 `ExitRequested`，事件循环被当场拆掉，交还只由 `RunEvent::Exit` 完成；开机自启的机器最容易只测前两条）。同一趟里归还引擎认领过的主输出音量。
- [ ] 设置 →「重置每应用音频输出」放开的是**当前挂着音频会话、又没有被本应用路由**的程序的固定端点（渲染与捕获两条流一起，Windows 那一侧没有"作者"字段可查）：**用户在音量合成器里手设的那几条一样会被清掉**——按钮文案与结果行必须按这个口径说，写成"只清旧版本留下的"就是假话；仍在路由的程序（连它同 exe 的兄弟进程）放过不动
- [ ] 启动提示：**第一次跑 2.3.x 的机器一律进全屏向导**（全新安装四步；从任何旧版本升上来先多一屏「是否继承以前版本的设置」——选「重新开始」会停掉刚恢复的路由并清空记住的路由/送入、延迟、设备份额、程序电平，选「继承」则原样保留；装过 2.1.0 或版本不可考的再加一屏「重置每应用音频输出」，该按钮只清理固定端点、与继承的选择无关）；点掉后同一版本不再弹（版本记在 `install-state.json`）；已经跑过 2.3.x 的机器再升级**不弹**；**没有升级弹窗这种东西了**——旧版提示已并入向导
- [ ] 向导的每一扇门都执行「重新开始」：答完这一屏后按 `下一步`、按 `跳过向导`、按 `Escape` 结果相同（以前只有 `下一步` 会动手——选了「重新开始」再跳过＝旧设置原样留着，而这一屏再也不出现）；清理被后端拒绝时**留在这一屏**、把原因写在选项下面（改选「继承」即可正常离开），窗口的 ✕ 始终是绝对出口
- [ ] 设置 →「关于」能**重新走一遍导览**（只有那四步：不再问继承、不再问旧端点；走完或跳过都回到设置页），以及按界面语言**打开说明文档**（`open_help_page` 只收 key，URL 固定在 Rust 侧；浏览器打不开时报错误卡，不是悄悄没反应）
- [ ] 启动向导：全新安装第一次打开是全屏四步向导（标题栏与窗口控制可用、设置入口隐藏）；载体一步点名检测到的回环驱动并可一键配对，没装时给 VB-Cable 下载指引；后台一步的两个开关真实落到注册表与 `app-settings.json`；完成/跳过/`Escape` 都 ack，同一版本不再出现；向导期间看板与左栏不渲染、退出向导后它们照常出现。**向导没有容器面板**——内容直接坐在工作区上（与设置页同款），
任何"包住整步的圆角面"不管有没有描边都是卡片，都是被否掉的形状；大圆角只长在真实的形状上（载体行、示意图卡取 `rounded-card`），
步进点是同心圆 `Ring`（当前步内芯点亮），切步时标题与正文**逐字由模糊到清晰**进场——一次性入场、不循环，控制件（行/开关/按钮）整块进场不做逐字
- [ ] 一个程序只路由一个进程，但账是**程序的**：拿浏览器（同 exe 十几个会话）试——只有最小 pid 拿到分配，可**非持有者的那一行**照样画成已路由、照样有 ✕、照样排在最前，hub 不会挂着「点按生效」，标题栏的「播放中」也数得上它（出声的常常是兄弟进程）。停路由时 ✕ 传的是持有者，不是这一行的 pid——传错了会静默不生效
- [ ] 自动记忆：开启后路由一个程序，重启本应用或让该程序重新出声，路由自动恢复且日志各留一行；手动停止过的不会被装回去；设置页能列出并「忘记」某条记忆
- [ ] 插上一个新设备 / 让一个新程序开始放音：不点 Refresh，两边列表自己跟上，且日志只在内容真的变化时多一行
- [ ] 首帧：左栏在第一份枚举返回之前说的是「正在读取哪些程序在放音…」（Spinner），**不是**「未检测到正在播放音频的程序」；枚举失败也算返回（占位不会永远挂着），失败由错误卡报告
- [ ] 一台输出设备都读不到时：「＋ 添加去向」与换主输出的选择器写「Windows 没有报告任何输出设备」，不写「没有可添加的了」——后者是一个完成的动作，这里没东西可动作
- [ ] 托盘图标常驻，左键开关窗口；右键菜单有「显示 / 隐藏」「打开设置」「开机自动启动」（勾选状态与注册表一致）「停止全部路由」「退出」，标签跟随界面语言，除显示/隐藏与退出外的动作都转到前端执行；开启「关闭窗口时最小化到托盘」后按 X 不退出、路由继续
- [ ] 开启「开机自动启动」后：注册表 `HKCU\...\Run` 有那一条、重启后只出现托盘图标不弹窗、开关状态仍与注册表一致
- [ ] 单实例：程序已经在运行时再次启动它，只把已有窗口唤到前台，不出现第二个托盘图标，也不重复起一份复制引擎
- [ ] 进程列表搜索：输入即时过滤，已路由的排在最前且组内顺序稳定；`Escape` 清空并失焦；无匹配时的提示与「没有进程在放音」不是同一句
- [ ] 节点看板：选中一个程序后它是 hub 卡（名字写在卡里），右侧是它的去向，分装在**两块虚线圆角矩形**里——上块是主设备（编号 01），下块是复制设备与应用输入（副本在前、送入的程序在后）；每行有编号角标（01 起，**编号即路由顺序**），hub 出脚到那一行的入脚之间一根灰线——**没参与的设备不在板上、也没有线**；「＋ 添加去向」在下块标题行里（选择器里设备与程序输入分两组）
- [ ] 送入程序：选中 A，经下块标题行的「＋ 添加去向」把 B 的输入加进来——那一行写「送入」并立刻生效（`set_feed_target`，没有 hub 那一步），Toast 给撤销；把 A 路由到设备后这一行改口写「挂起」（渲染槽被占），停掉设备路由后自动恢复；设置页没配载体时写「未接通」且日志点名原因；设置页选好回环端点对后挂起/未接通的送入自己接通
- [ ] 送入载体的检测与引导：装了 VB-Cable/VoiceMeeter 的机器，设置页点名检测且「一键配对」把端点对写进载体（看板上的送入行随之从「未接通」变「送入」）；没装且载体未配置时给出 VB-Cable 下载指引，点击打开官方页（`ShellExecuteW`）；**已配置载体时不出指引**；装完驱动不重启应用，设备列表自动跟上、即可配对
- [ ] 载体藏进后台：设置页配好载体的**播放侧**后，看板的「＋ 添加去向」与「换主输出」两个列表里都不再出现那台虚拟声卡（按 `feedCarrier.render` 精确匹配，不做名字/回环驱动探测；只配了播放侧也算配）；**设置页的载体下拉与一键配对仍看得到完整设备列表**；系统默认输出恰好是它时照旧 staged、照旧画行、照旧可 apply；它已在计划里时换主输出菜单里照旧列出它并带勾、还能把它换出去；左栏、现状页、已路由胶囊不受影响；载体未配置（或只配了录音侧）时设备全集照旧
- [ ] 计划永不被点空：路由里只剩一台时点它被忽略、它的 ✕ 也不出现（守卫在 `NodeStage` 的 `toggleTarget`，不在 store）；加入一台计划外的设备只有「＋ 添加去向」这一条路，它**只追加**（见下两条）——所以 2.1.1 那句「第一次点另一台是替换」在今天**没有可点的入口**，别按那个口径验收（`replacesGuess` 仍写在 store 里，理由见 [state.md](./state.md)）
- [ ] 换主输出：多设备计划中副本的角色词带点状下划线，悬停/聚焦由「副本」变「设为主输出」，点击后两张卡的角色词当场对调、按下 hub 后后端收到以它为首的设备顺序（**按计划顺序落地，任何副本都可换，不设补偿门槛**）；卡片角色词、hub `aria-label`、落地顺序三处一致
- [ ] hub 卡即应用：有改动待生效时它是一枚按钮（卡上挂「点按生效」胶囊与 accent 描边，`aria-label` 是完整句子、列出全部去向），按下即落地并给 Toast 撤销；画面已经是事实时它不可按（胶囊消失、`disabled`）；未选中程序时板上是一句引导；丢弃已选改动 = 重新选中那个程序（计划被事实读回，不发任何 apply_route）。**程序自己的去向摘要不常驻在任何地方**——它在「现状」页里（底部不再有常驻条）
- [ ] 已路由胶囊：有路由时工作区底部中央出现「已路由 n」，点开列出每个正在路由的程序一行（名字旁点名去向，Ring 报告在不在响）；点名字跳到它的看板（调音去那里，浮层里不复制延迟/音量控件）；行尾 ✕ 二次确认后停止该程序、行随路由一起消失；全部停止后胶囊整颗消失；**这里只有停止，没有开始**；某台设备在两次刷新之间走掉了，那一行的去向写「一台已经离开的设备」，**不写 GUID**（现状页同一条；看板上那一行的行名与 hub 的 `aria-label` 说的也是同一句，`Inspector` 里同样不拼 GUID）；程序多时浮层**不长成一屏**——列表按 `SHEET_LIST_MAX_PX`（280）封顶，超出在内部滚
- [ ] 现状页：标签页排在「路由」与「活动记录」之间；没改道时说清都跟着系统默认设备走并给出该设备名；每个已路由程序一行——图标 + 名字 + 连线 + **去向 chip**（角色色圆点 + 名称 + 角色词，主输出在前）；送入 chip 用琥珀色并写「输入 / 挂起 / 未接通」，非 live 的变淡；未在播放的行缀一句；点行里的名字跳回「路由」标签页并选中该程序；有未落地改动时底部补一行怎么生效；旧的「直说」浮层与其文案已不存在
- [ ] 主设备可换：点主设备行的名字或角色词弹出选择器；选一台已在计划里的设备 → 两行角色对调（计划成员不变）；选一台计划外的设备 → 它接任主位、**计划数组的第一台**离开、其余不变；当前主设备在选择器里带勾；**任何设备都能被选为主输出——带着延迟补偿的也可以**（补偿值只影响引擎基线，不设门槛、不显示禁用行）；选择器里可点的项，点了**一定**会生效（与 store 的判定同一套）；都只改计划，按下 hub 才落地

- [ ] 本应用不出现在左栏：自己放音（或 WebView2 子进程放音）时，程序列表里没有本应用/它的子进程
- [ ] 单实例：程序已经在运行时再次启动它，只把已有窗口唤到前台（第一次启动若在窗口建出来之前被抢跑，唤窗线程仍在等，不会提前退休）
- [ ] 批次：左栏行末那颗圆形开关能把另一个程序并进这次改动（不知道 Ctrl 也能做）；Ctrl+点击名称做同一件事，两处的状态一致；**它常驻可见**（未悬停时淡一些，悬停/聚焦回到实色）——只在 hover 才出现的控件对触屏与笔等于没有
- [ ] 声流：只有画出来的路线与正在生效的完全一致、且程序在响时，线才跑流动虚线；程序一停虚线消失（卸载，不是暂停）；把窗口切到后台或失焦，**线与脉冲环都被卸载**，静止界面不产生任何重绘；系统「减少动态效果」开启时同样静止
