# 节点看板 UI 规范（2026-10-05 改版，2026-10-10 分组，专题）

> 本文是 [AGENTS.md](../../AGENTS.md) 的专题延伸。改 `NodeStage`、`ProgramRail`、`StatusBriefing`、`RoutedCapsule`、调音条、看板几何之前先读这里；每条 ⚠️ 都是踩过的坑。令牌与阴影见 [theme.md](./theme.md)。

---

路由页是一张**节点看板**：**左中是当前程序**（hub 卡），**右上是它的主设备**、**右下是它的复制设备与应用输入**——
去向被分成两块**虚线圆角矩形（panel）**，hub 的**出脚**到那一行的**入脚**之间那根线**就是**路由的这一段。
这一屏回答的是「**这个程序的声音正往哪儿去**」——线连着谁，声音就去哪儿，眼睛不必先读完一行列头。

视觉语言是**实底面板 + 1px 细线 + 同心圆**（`Ring`），外加一件新东西：**编号角标**（`.no`，01/02/03…）。
**编号就是路由顺序**——01 永远是主输出（由 Windows 直接播放的那台），之后是副本，再之后是送入的程序输入。
颜色长在角标与角色词上，**不在线上**：这是这一版从达芬奇调色页借来的那一条，也是它不乱的原因。

## 为什么是这个形状

历次改版各有各的复活风险，逐条写明，别把删过的东西再拿回来：

| 版本 | 内容 | 现状 |
|------|------|------|
| ① 液态玻璃 + 同心圆舞台 + 胶囊节点 | `ConcentricRouter` / `DeviceAnnotation` / `OutputStatusBar` / `useFitScale` / `useDecorativeMotion` | 已删 |
| ② 路由树 | `RouteFlow` / `RouteSubject` | 已删，不要复活：同一批设备讲两遍，两遍的排序依据还不同 |
| ③ 扁平编辑器式 + 设备表格 | `DeviceTable` | 已删：表格说得出路由由什么组成，说不出「流向」 |
| ④ 节点画布（自由布局） | `RouteCanvas` / `EdgeLayer` / `SourceNode` / `DeviceNode` / `RouteConfirmCapsule` / `lib/canvas.ts` / `--canvas-grid*` | 已删，**不要以"自由画布"的形式复活**：可拖摆的画布 = 可以被摆乱，还要平移缩放、ResizeObserver 与"动画期间钉住被测那一帧" |
| ⑤ 同心圆舞台（圆环 + 圆盘 + 辐条） | `ConcentricStage.tsx` | **2.3.0 已删**：一个程序的去向只有一列时环形毫无用处，而"程序 → 程序"进来之后路由不再是一颗星，环形撑不住 |
| ⑥ 节点看板（当前） | `NodeStage.tsx` + `lib/stage.ts` | 是**固定布局**的节点图：位置由路由顺序算出来，没有拖动、没有平移缩放、没有画布管理——节点是系统的（程序、设备、程序输入都是枚举出来的），用户永远不需要"创建"任何东西 |
| ⑦ 去向分两块虚线面板（2026-10-10） | `Panel`（`NodeStage.tsx`）、`GROUP_X/GROUP_W/PANEL_BORDER`、`panelColumn` | 在 ⑥ 之上只做了一件事：把右侧一列**按角色装进两个虚线圆角矩形**——主设备一块、复制设备与送入一块；装了卡片的矩形不能画成卡片，所以用虚线。两块面板合成**一列、在 hub 上居中**，所以线从 hub 出脚同时向上（主设备）和向下（其余）伸 |
| ⑧ 主设备可换、复制面板半行收尾、调音条按需、现状成页（2026-10-11） | `setPrimaryDevice` / `appendDeviceTarget`、`peekBodyHeight`、`Inspector` 的按需挂载、`BriefingPage` | 主设备行不再是死标签（点它弹出换主设备选择器）；「＋ 添加去向」**只追加副本**（不再替换预填的猜测）；复制面板装不下时**以半行收尾**并加一层背景渐隐；调音条只在点了某一行编号时存在（底部不再常驻 status bar）；「直说」从浮层变成**路由与活动记录之间的「现状」页** |

⑥ 保留下来的旧资产：**`Ring` 同心圆**（卡片上的状态标记）、**点按生效**（计划/事实两段式）、
**调音条**（角色决定有哪些杠杆）、**流动虚线**（正在出声）。⑥ 新增的词汇只有两个：**编号**（顺序）与**琥珀色**（程序输入）。

## 计划与事实（`drawn` / `live`）

- `drawn = selectedDeviceIds` 是**计划**，`live = routedPids[pid]` 是**事实**。选中一个程序时，store 用事实（无路由时用系统默认设备）预填计划，
  所以刚选中时屏幕上出现的是现实；动过手之后出现的是待办的改动。
- ⚠️ **看板画的顺序是落地时采用的顺序**（`orderByDelay`，稳定排序），不是 `selectedDeviceIds` 的原始顺序：没配延迟时两者一致，
  配了延迟时角色词当场落在真正会坐主位的那台上——预览不许说谎。hub 的 `aria-label`（`stage.applyAria*`）与 `alreadyApplied`
  （`lib/stage.ts`，有单测）读的是同一份顺序。
- ⚠️ **hub 不许自称计划是事实**：待生效时它是一枚按钮（带「点按生效」胶囊与 accent 描边），
  已经是事实时它 `disabled`、退回一块普通面板——"你正在看着答案，不该再问你一遍"。
  程序自己的摘要（从哪几台出声、送入几个）常驻在底部**调音条**里，与它是不是按钮无关。

## 看板几何（`lib/stage.ts`）

`BOARD_W(640)` / `BOARD_H(470)` / `HUB_W(190)` / `HUB_H(84)` / `HUB_X(160)` / `GROUP_X(382)` / `GROUP_W(212)` /
`GROUP_PAD(6)` / `GROUP_HEADER_H(24)` / `PANEL_BORDER(1)` / `ROW_X` / `ROW_W` / `ROW_H(52)` / `ROW_GAP(6)` /
`MINI_W(120)` / `FEEDER_X(12)` / `PIN_D(11)` 是**唯一的**尺寸来源，由 `panelColumn()`、`panelBodyHeight()`、
`primaryPanelHeight()`、`rowContentY()`、`rowPortY()`、`rowInPort()`、`rowVisible()`、
`feederY()`、`hubOutPort()`、`hubInPort()`、`feederOutPort()`、`nodePath()` 算出位置与线两端。
组件用 `style` 从这些常量取宽高与坐标，**不要**改成 Tailwind 的 `w-[…]`：尺寸在两处各写一份，线迟早会离开卡片。

⚠️ **尺寸唯一的度量是井的高度**：`BOARD_H` 只在第一帧（井还没报高度时）顶一下，此后板子**正好等于井的高度**
（`useElementHeight`，全项目唯一一处 ResizeObserver）。**舞台区永不滚动**（`overflow-y-hidden`）。
⚠️ **两块面板是列，不是两块独立的东西**：`panelColumn(height, rows)` 一次给出整列的四个数——
主设备面板固定一行高，复制面板取**内容**高度（空面板与一行高的面板一样高，免得第一台副本到场时整列跳一下），
整列**在 hub 的横线上居中**。这就是「排布平衡」的全部机制：线从 hub 的出脚同时向上（主设备）和向下（其余）走。
⚠️ **不要把它改成「复制面板吃掉剩余高度」**（2026-10-11 之前是这样）：那会让少设备时右下方空出一大块虚线框、
整列偏左上，看着不平衡。行装不下时**复制面板自己滚**（`overflow-y-auto`），板子仍然不长高。
⚠️ **装不下时面板以「半行」收尾**（2026-10-11）：`panelColumn` 走 `peekBodyHeight`，面板高度取「装得下的整行 +
下一行的中点」——底边正好落在某一行的中心，于是**半张卡片露在裁切线以上**，这行本身就在说「下面还有」。配合
`Panel` 里那两层 `bg-gradient-to-* from-surface-sunken` 的**背景渐隐**（只在对应方向还有内容时淡入，`opacity` 过渡）：
半行 + 渐隐一起构成「底部有东西在拉」的滚动提示。⚠️ 渐隐是**背景色渐变**不是 blur/黑罩，别把它做成遮罩层或加 `backdrop-filter`。
⚠️ 面板那 1px 描边也算进几何（`PANEL_BORDER`）：行是在**边框之内**再加内边距的，
少算这一像素，每根线都会停在它那一行的左边一像素（这条踩过，`rowPortY` / `ROW_X` 里都写死着它）。

⚠️ **线跟着行滚**：去线的端点由 `rowPortY(panelY, index, scrollTop)` 给出，`copyScroll` 是复制面板的滚动量。
滚出面板的行**不画线**（`rowVisible`）——画了它会跑到面板外面，指着一行看不见的东西。
线在面板**左侧描边上结束**，行内那只 `pin-in` 的中心正好也在那儿（`.pin-in` 是 `left:-5.5px`，即居中在边上），
所以线是插在描边上、不是插在行里。

同一条理由决定了这里**没有拖动、没有平移、没有缩放**：位置仍由路由顺序决定 → 几何是算术。
唯一的度量是**井的一个高度数字**，整块板子都由它算出来，所以行和线仍在同一帧里对齐；
`getBoundingClientRect` 在这里会让每根线比每段弹簧晚一帧。

## 三类卡（hub / 去向 / 来源）

- **hub**：当前程序。名字、图标、`Ring`（有计划时 main）、状态词（正在播放/未在播放）、`stage.feedCount`（送入几个）。
  待生效时它是按钮（点它 = `applyRoute`），已生效时 `disabled`。多设备路由时电平环挂在它下面（`drawn.length > 1`）。
- **去向面板（右侧两块虚线矩形）**：上块只装**主设备**（编号 01，`drawn[0]`），下块装**其余全部**——副本在前、送入的程序在后。
  面板本身不是卡片（它装卡片），所以画成**虚线**；标题行常驻，不随行滚动。
  ⚠️ 下块的滚动条只属于下块（`overflow-y-auto`），**永远不要**把它挪到井上：舞台一滚，
  「板子正好等于井的高度」这条前提就没了，线也不再跟得上行。
  ⚠️ **主设备那一行不是死标签**（2026-10-11）：点它（名字按钮或角色词）弹出**换主设备选择器**
  （`setPrimaryDevice`，标题行里没有按钮，选择器挂在主设备面板下方）。选一台**已在计划里**的设备 = 两者角色对调
  （老主设备降为副本，计划成员一个不少）；选一台**计划外**的设备 = 它接任主位，副本原样留下。延迟补偿严格更大、
  不可能坐主位的设备在选择器里**禁用**并给 `title` 解释原因（同一套 `promoteBlockedTitle` 文案）。
  那一行的角色词在悬停/聚焦时由「主输出」变「更改主设备」，`aria-label` 是动作——与副本那行同一种手势。
  每行都是**行**而不是卡：编号角标（`.no`，现在领在行首而非压在角上）、名字按钮、角色词/操作、行尾 ✕。
  名字按钮**点按 = 进出这条路由**（`toggleTarget`，最后一个设备不可移除——"路由不可能被点空"的守卫在这里，不在 store）。
  副本的角色词就是**换主位的开关**：平时写「副本」，悬停/聚焦变「设为主输出」，
  `aria-label` 是 `stage.promote`（读屏听到的是动作）。延迟补偿严格更大的副本没有这个开关，`title` 解释原因。
  送入行（琥珀）写「送入 / 挂起 / 未接通」三态之一，✕ 立刻断开（走 Toast 撤销，不是计划）。
  「＋ 添加去向」是下块标题行里的一枚小虚线圆钮（`stage.addTarget` 仍是它的无障碍名），选择器挂在它下面；
  它从原来那张虚线卡片搬到这里，是为了**无论行有多少都够得着**。
  ⚠️ 选择器里的设备行走 `appendDeviceTarget`（**只追加到计划尾部 = 副本**），**不要**改回 `toggleDeviceSelection`：
  后者带着 `replacesGuess` 语义，在计划还只有预填的一台设备时会把那台**替换掉**——用户想「加一台」，结果新加的坐了主位、原来的没了。
- **来源卡（左侧一列）**：谁把声音送进了当前程序。点它**切到那个程序的看板**——图一次讲一个程序，这是两个程序之间的门。

## 编号与调音条（`Inspector`）

- **角标即调音入口**：点去向卡的编号，底部调音条切到那张卡的杠杆——主输出=会话音量一行，副本=延迟 + 份额两行。
  ⚠️ **单设备路由没有编号按钮**（那是 `span`，不是按钮）：一个设备的路由由系统直放，没有引擎，也就没有可调的杠杆——
  与旧舞台同一条规则。`drawn.length > 1` 是唯一条件，别为单设备路由特例盖章。
- ⚠️ **调音条按需出现，底部没有常驻 status bar**（2026-10-11）：`Inspector` 只在 `inspectorKey !== null` 时**挂载**
  （外层 `AnimatePresence` + `height: auto` 让它自占地、离开时把空间还回去）。曾经它常驻在底部、没选中时显示一句提示语——
  那是一条谁都不会读的状态栏。被检查的那台设备**离开计划**（被移除，或计划降到一台、不再有引擎）时，
  `NodeStage` 里的 effect 会把 `inspectorKey` 清空，所以 `Inspector` 可以假定自己指的那一行一定在计划里；
  它也因此**不再有 hub 摘要分支**（'hub' 这个 key 已随常驻形态一起删掉，别再搬回来）。
- 调音条里**没有**开始/停止路由的按钮：开始只属于 hub（点按生效），停止属于左栏行内 ✕ 与底部中央的已路由胶囊
  （见「已路由胶囊」）。别把动作塞回调音条——它是调音的地方，不是运输控制的地方。
- **± 按钮的 aria-label 沿用旧词表**（`deviceDelay.stepUp/stepDown`、`deviceVolume.*`、`primaryVolume.*`），
  值里的单位也跟着角色走（延迟带 `ms`，音量带 `%`）。
- ⚠️ **实测延迟仍然只在 tooltip 里**（`deviceLatency.reading`）：它是读数不是控件，主输出那条没有它（没有属于我们的流）。

## 送入（feed）：2.3.0 的新路由形态

- 送入**不是计划**：它两端各钉一个端点（源 → 载体的播放侧，目标 ← 载体的录音侧），所以**选中即生效**，
  撤销由 Toast 提供（`feedUndo`）；这一点与设备路由的两段式不同，是有意的——两端都被钉住的关系没有"预览"可言。
- 三态由 `feedLiveness()` 判定，卡上照实写：
  **`live`（送入）= 载体已配且源没被设备路由占着渲染槽**；
  **`suspended`（挂起）= 源正输出到设备**——每应用只有一个渲染槽，被路由占了，停掉那条路由后送入自动恢复（`stop_route` 里就地把载体钉回去）；
  **`no-carrier`（未接通）= 设置页还没选端点对**，规则照记，声音不动。
- ⚠️ **渲染与捕获是两个数据流**：`PinnedRoutes` 里分成两本账（`mark_feed` / `mark_feed_capture`），
  释放也分（`release_process_default_devices_flow(…, capture)`）。停止一条设备路由**不能**顺手清掉捕获侧——
  那个程序还可能在收别人的声音。只有"重置每应用音频输出"与退出这两条路会两个流一起清。
- ⚠️ **别把送入并进设备路由的记忆**：`feed-memory.json` 与 `route-memory.json` 是两份，
  一条规则的存在不依赖另一条；恢复也各自独立（`restoreRememberedFeeds` vs `restoreRememberedRoutes`，都由列表/记忆/载体的到达触发）。
- **设置页会点名探测常见回环驱动**（`lib/carrierDetect.ts`：VB-Cable、VoiceMeeter；按友好名的子串匹配、
  不区分大小写，VoiceMeeter 的标记故意不命中 Aux 对——「… Aux Input」截断了子串，Banana/Potato 系统配的是 VAIO 对）。
  检测到就给「一键配对」（走现成的 `setFeedCarrier`）；没检测到**且载体未配置**时给 VB-Cable 下载指引——
  `open_carrier_download` 的 URL 映射固定在 Rust 侧（`commands.rs` 的 `CARRIER_PAGES`），前端只传驱动 key、永不传 URL，
  页面经 `ShellExecuteW` 的 open 动词交给浏览器关联。探测只是认名字，**不是携带**：应用仍然不自带、不安装任何驱动；
  已配置载体但不是已知驱动时保持安静（用户自己配的，别念叨）。
- 两份设备列表都随 `audio-changed` 刷新（`syncFromNotification` 的 devices 分支也拉捕获列表），
  所以「装完回环驱动 → 不重启 → 一键配对」这条链是闭环的，别把捕获列表从那条路里摘出去。

## 布局与其余规矩

- `App` 根节点 `relative isolate`，背景就是 `--bg-primary` 那层纯色平面，**标题栏透明**。
  下面是 `aside`（236px + `border-r border-line`）＋ `main`（`relative`，给浮动件一个锚点）＋ `UnderlineTabs`（**路由 / 现状 / 活动记录**）。
- **路由只由看板表达**：线就是路由。**别在别处再画第二份**（树、状态条、常驻的文字摘要）；
  有几个**点名的**例外：**「现状」页**（一个标签页，见下节）与**已路由胶囊**（所有路由的管理面）。
  左栏第二行说"这个程序从哪台设备出声"是列表的本分，不算第二份路由图。**底部不再有常驻 status bar**。
- **左栏选中行的形状是圆角矩形，不是胶囊**（2026-10-11）：行是 `rounded-ctl`，选中面是同一形状的实底 + 行首一根 2px accent 竖规，
  两者用 `layoutId="rail-selection"` 在行间**滑动**。批量加入的行用 `bg-accent/[0.07]` 的淡洗。**别改回 `rounded-full`**——
  胶囊会把每一行读成按钮，而这里是一份列表。
- **accent 只用来标记"属于路由的那部分"**：左栏的选中行、hub 待生效的描边与胶囊。角色词按角色上色（那是编码本身）。
- 数字与标识符（PID、毫秒、百分比、版本号、exe 名、角标编号）用 `font-mono tabular-nums`。
- **误操作防护**：① 看板只是提案，改动要按 hub 才落地（送入例外，见上）；② "也改这个"有看得见的开关；
  ③ 破坏性且影响全局的动作用 `ConfirmButton`；④ 路由与送入后 Toast 各给 8 秒撤销。路由不可能被点成空的（最后一个设备卡不可移除）。
- **i18n**：文案分组是 `rail` / `stage` / `briefing` / `settings` / `toast` / `log`，
  两组 locale 的键集合、占位符与非空由 `src/i18n/locales.test.ts` 的对称测试保护。
  句子说人话，避开"路由 / 镜像 / 主设备"这类内部词。
- **禁止**：胶囊状的**标签页**（标签仍是下划线，`layoutId` 迁移）、常驻装饰循环
  （背景漂移、轨道环；**线流动与脉冲环是唯二的例外，且必须走卸载式闸门**）、看板的拖动·平移·缩放、自由摆放的节点、
  第二份路由摘要、把延迟/音量画到主输出上（包括"变淡地画"）、给同心圆家族加任何非正圆的形状。
- **动效**：全部取自 `lib/motion.ts`——`SPRING_TAP`（卡片按压、行内的微交互）/ `FADE`（纯透明度入场）/
  `SPRING_GLIDE`（有位移的视图切换），**不要在调用点现调参数**：邻居之间弹得不一样看着像 bug，不像设计。

## 现状页（`BriefingPage`，2026-10-11 取代「直说」浮层）

工作区标签页的第二页，排在**「路由」与「活动记录」之间**（`tabs.briefing`）。它回答「此刻所有程序都把声音送到哪儿」，
而且**用图回答**：每个被改道的程序一行，左边是图标 + 名字 + `Ring`，中间一根带箭头的短线，右边是一串**去向 chip**
（角色色圆点 + 设备/程序名 + 角色词），顺序就是声音到达的顺序（主输出在前）。页面顶部先给**系统默认设备**那条基线，
并写明还有几个程序跟着它走——这一页讲的是例外，所以规则排在例外前面。

- 没有改道时：一句「还没有任何程序被改道」+ 系统默认设备名，`Ring` 作插图。
- 送入的 chip 用琥珀色，并按 `feedLiveness` 写「输入 / 挂起 / 未接通」，非 live 的整颗 chip 变淡。
- 底部（`briefingPage.staged`）在有未落地改动时补一行：**回到「路由」按下程序卡即可生效**。
- 行里的名字是**门**：点它 = `selectProcess` + 切回「路由」标签页（`onOpenBoard`）。这一页**只报告，不操作**。
- ⚠️ **它是「路由摘要」禁令的第二个例外**（第一个是旧浮层）：它是一个**标签页**，不是常驻条、不是第二块看板，
  而且是被明确要求做出来的。别据此再把摘要画回看板之外的其他地方。
- ⚠️ 旧的 `StatusBriefing`（左下角「直说」小胶囊 + 纯文字气泡）与它的 `briefing.*` 文案**已删**，不要复活。

## 已路由胶囊（`RoutedCapsule`，2026-10-07 起）

工作区底部中央的一颗胶囊（「已路由 n」，`bottom-[56px]` 居中——老 ActionDock 的位置），
点开向上展开一张实底浮层：**每个正在路由的程序一行**。它是看板的对立面补全：看板只答"这一个程序去哪儿"，
胶囊答"**所有**程序都去哪儿"。

- **只有停止，没有开始**：开始路由只属于看板的 hub（计划在那里、预览在那里）；胶囊是已存在路由的管理面。
- 行内三样东西：`Ring`（在不在响，走 `useLiveness` 闸门）+ 名字按钮 + 行尾 ✕（`ConfirmButton`，
  确认词复用 `rail.stopRoute` / `rail.stopRouteConfirm`，与左栏行内 ✕ 同一套、同一条 `stop_route` 路径）。
- **名字是门，不是杠杆**：点名字 = `selectProcess` 跳到那个程序的看板，调音条里单独调整。浮层里**不复制**
  延迟/音量控件——同一个数在两个地方能改，一定有先后之争。
- **没有路由时整颗胶囊不存在**（与标题栏计数同一条规矩）；列表被停空时浮层自己收起。
- ⚠️ 行按会话列表走，不按路由表走：正在退出的进程可能还挂着路由，但没有名字和图标可画（现状页同一条读法）。
- ⚠️ `Escape` / `pointerdown` 监听跟浮层可见性同注册同注销（与看板选择器同款）。

## 左栏（`ProgramRail`）

每行：一枚 `Ring` + 程序名 + 第二行 `PID xxx`（只有已路由的行才追加 `· 设备名 +n`）。
行末那颗圆形小开关（`MiniToggle`）"同时更改此程序的输出"取代了 Ctrl+点击；排序为"已路由在前、组内稳定"。

## 设置页（`SettingsPage`，2026-10-11 改版）

布局是**一条分区导航 + 右侧内容**：左侧 190px 的 rail（返回、六个分区、版本号），一条竖细线，右边是当前分区的行。
分区：外观 / 路由 / 后台运行 / 延迟补偿 / 程序电平 / 关于。选中分区由一根 `layoutId="settings-section-rule"` 的
**左侧竖规**标记（不是胶囊）；内容区用 `AnimatePresence mode="wait"` 做一次纯透明度换页。

- ⚠️ **改版前的单列长滚动是错的**（外观、路由、延迟、关于全挤在同一条滚动里），别再合并回去。
- **载体下拉是自研的 `ui/Select.tsx`，不许换回原生 `<select>`**：原生菜单不可样式化、不可动效。它是完整的 combobox
  （Enter/Space/↓ 打开、方向键与 Home/End 移动、Enter 选中、Escape 关自己）。它带 `data-owns-escape`，

- 正文里的数字/版本号仍用 `font-mono tabular-nums`；分区里的行仍是"左标题右控件 + 下划线"。没有卡片、没有阴影。
